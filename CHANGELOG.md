## v1.9.0 - v1.9.0

*Released: 10/4/2026*

Version 1.9.0 - Remove links from subtitles

New opt-in option: **Settings → Processing → "Remove Links from Subtitles"**
(off by default). Implements #14.

When enabled, dropped subtitles are scanned for:

- URLs — `http(s)://`, `ftp://`, `magnet:`, bare domains, `www.` hosts
- Email addresses
- IPv4 addresses, with optional port and path
- Obfuscated links — `example (dot) com`, `example [.] com`,
  `www dot example dot com`, `hxxp://`
- Social handles — `@releasegroup`

Nothing is changed silently. A preview dialog lists every match with its
line number and category, shows a live before/after diff, and lets each
match be unchecked individually before anything is applied.

Matching is conservative, because subtitles are not clean prose:

- A dotted token counts as a domain only when its last label is a real
  delegated TLD, so `example.com` is stripped while `example.commute`
  is left alone.
- 107 TLDs are also common sentence-starting English words (`.it`, `.to`,
  `.me`, `.now`, `.one`). Subtitles frequently drop the space after a
  period, so those need a scheme, a `www.` prefix, or a path/port before
  they count as links — `"Stop.It's over"` and `"I know.Now go"` survive,
  `http://stop.it` and `stop.it/freesubs` do not.
- A Title-Cased TLD is treated as a sentence boundary; ALL-CAPS still
  matches, so `VISIT EXAMPLE.COM` is caught.

Subtitle structure is preserved. Timing lines, indexes, ASS headers and
MicroDVD frame markers are never touched. Cues left holding nothing but a
link are dropped and the remaining ones renumbered. Edits are applied over
a byte-preserving latin1 view, so cp1250/cp1251/Big5 files keep their
original encoding byte-for-byte.

The TLD list is generated from IANA via `npm run generate-tlds`.
Covered by 99 new unit tests.

## v1.8.22 - v1.8.22

*Released: 9/7/2026*

Version 1.8.22 - Session keep-alive and auth robustness

Keep the OpenSubtitles session alive while the app is open, and stop
transient network failures from logging users out.

The app stores a server-issued PHPSESSID as its session token. The server
expires it six hours after the last request (Set-Cookie Max-Age=21600),
and nothing was refreshing it.

Session keep-alive:
- Add XmlRpcService.noOperation() and an hourly keep-alive ping
- Ping is best-effort: it never mutates authentication state, because
  NoOperation answers 200 OK even for tokens the server never issued
- Guard against timer stacking, stale in-flight state, and hung sockets
- Revalidate with a fresh GetUserInfo on wake/refocus after an idle gap,
  bypassing the one-hour user-info cache

Authentication fixes:
- checkAuthStatus no longer discards stored credentials when the server
  is simply unreachable; only an actual rejection logs the user out
- Return the verdict instead of stashing it on the service singleton,
  which two concurrent StrictMode inits could clobber
- Retry an unverified session when connectivity returns
- Await restoreAuthFromStorage; a promise is always truthy

Latent bugs found by fixing the ESLint parser:
- updateService: downloadPath/totalBytes were block-scoped to the try but
  read in the catch, so the signature-validation download fallback threw
  ReferenceError instead of running
- DebugPanel: same pattern left the older-browser clipboard fallback dead

Security:
- Stop logging partial session ids and tokens in SessionManager,
  sessionUtils, DebugPanel and TryUploadSubtitles
- DebugPanel no longer copies a token prefix into the clipboard blob
- Escape the token in every XML-RPC request body

Housekeeping:
- ESLint ecmaVersion 2021 -> 2022; static class fields broke the parser,
  leaving eight service files silently unlinted
- Store the session under the key detectSession actually reads, and purge
  the orphaned write-only opensubtitles_session_id
- Collapse two XML escapers into one, and make it null-safe
- Sync Cargo.lock, stale since 1.8.18

## v1.8.19 - Extracted MKV Subtitles Fix

*Released: 7/16/2026*

## 🐛 Bug Fix: Extracted MKV Subtitles Classification

Fixed extracted MKV subtitles being incorrectly classified as orphaned subtitles, which prevented them from displaying episode numbers.

### What was broken
- When subtitles were extracted from MKV files, they were sometimes treated as orphaned instead of paired with the source video
- Orphaned subtitles display differently in UI (without episode info from the paired video)
- This was a race condition in subtitle pairing detection

### What's fixed
- Extracted subtitles now explicitly check `pairedWithMkv` flag to prevent orphan classification
- Subtitles extracted from MKV are now correctly recognized as paired, not orphaned
- Episode information now displays correctly for extracted subtitles

### Files changed
- SubtitleUploader.jsx: Added `pairedWithMkv` flag check in orphaned subtitle filter
